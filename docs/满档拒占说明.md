# 满档拒占说明（钉死口径，当日不得改口）

## 缺陷

占位服务算可占席时漏扣 `占位中` 席位：`pending` 恒为 0，可占席被算大。
结果是晚场显示售罄、黄牛仍可插入占位，满档占位不被拦住，候补区收不到溢出。

## 唯一正确性口径：甲路径（满档整笔回滚拒占）

> 本仓库只走甲路径，**不启用**乙路径（满档核销影子切换），两条路径不得混用。

可占席定义（全仓唯一口径，五处同态都从 `slots_svc.seat_view` 取）：

```
可占席 = 容量 - 已订 - 占位中
占位中 = SUM(holds.seats WHERE status='占位中')
```

请求席位数 > 可占席时：

1. **占位零增**：不写 `holds`，不产生任何 `占位中` 行；
2. **整笔回滚**：占位写入路径整体回滚，不留下半笔数据；
3. **转候补**：写一条 `waitlist`，`reason` 为 `满档`（可占席为 0）或 `容量不足`（仍有残席但不够）；
4. **记满档审计**：满档时写 `audit_trail.action='hold_full_reject'`，携带可占席、占位中、请求席；
5. **拒写与审计同败**：候补写入与满档审计在同一事务内，任一失败则两者都不落库，请求报错；
   **禁止**出现“审计写了、候补没写”或“候补写了、审计没写”。

非满档但有残席不足的，仍走原有 `hold_to_waitlist` 审计，不冒充满档。

## 并发：两人同时抢满场

- 占位必须先抢档锁 `slot:<code>`；锁先行落库，后到请求才看得见。
- 先到者持锁；后到者返回 409「争用：后到只记争用，不写业务」。
- 后到者**只留争用痕**：`contention_log` 一行必须随失败提交落库，且不得写占位、候补、满档审计。
- 争用痕不得随业务事务回滚被吞掉。

## 五处同态

| 面 | 同态要求 |
|----|----------|
| 占位中 | 仅统计 `status='占位中'`，满档拒占后零增 |
| 候补 | 满档溢出落 `候补中`，不空 |
| 可占席 | `capacity - booked - pending`，满档为 0；`sold_out` 由同一值判定 |
| 对账灯 | `booked` 与正式册同源，且 `booked + pending <= capacity`；否则灯红 |
| 审计 | 满档拒占留 `hold_full_reject`；失败时与候补同败 |

**禁止只改售罄角标**：只改 `sold_out`、不改占位校验/候补/对账/审计，视为未修。

- `tests/test_full_slot.py::test_two_racers_full_slot_later_only_leaves_contention_trace`

- `tests/test_full_slot.py::test_full_reject_audit_failure_rolls_back_refusal_write`

## 偏航判定

出现下列任一情况即记「满档拒占偏航」，不得合并：

- 改用乙路径或甲乙混用；
- 只改 `sold_out` / 只改文案；
- 满档仍写入 `holds`；
- 争用痕随事务回滚丢失；
- 候补与满档审计不同败。
